# CheckPhNumber bot

Техническое описание репозитория для разработки. Продуктовая идея — в `docs/project-idea.md`.

Бот отвечает в Telegram, какому оператору и региону выделен номер, по открытому реестру российской системы и плана нумерации. Поиск идёт по заранее развёрнутой базе SQLite. Сбор базы и работа бота — два отдельных запуска, общего процесса у них нет.

## Стек

| Компонент | Версия / инструмент |
|---|---|
| Язык | Python 3.12 (интерпретатор окружения: 3.12.13) |
| Окружение | `.venv` в корне, создаётся как `python3.12 -m venv .venv` |

| Хранилище | SQLite через стандартный `sqlite3` |
| Загрузка исходных данных | bash + `wget` (`getcsv.sh`) |
| Тесты, линтер, Docker, CI | нет |
| `requirements.txt` | нет; зависимости ставятся в `.venv` вручную: `aiogram`, `python-dotenv` |

Системный `python3` на машине — 3.10.12. Для проекта нужен интерпретатор `.venv` или явный `python3.12`.

Секреты: переменная `API_TOKEN` в `.env`. Шаблон — `.env.example`. Каталоги `.venv/`, `db.sqlite/` и `inCSV/` в `.gitignore`.

## Поток данных

```
opendata.digital.gov.ru
        │  getcsv.sh (wget, четыре CSV)
        ▼
   inCSV/*.csv
        │  parsetodb.py: каждая строка-диапазон
        │  разворачивается в отдельные номера
        ▼
db.sqlite/numeration_registry.db
        │  main.py: SELECT по fullnumber
        ▼
   ответ в Telegram: оператор (регион)
```

`inCSV/archive/` парсер не читает. `glob` берёт только `./inCSV/*.csv`.

`getcsv.sh` кладёт файлы в текущий каталог (`-O ABC-3xx.csv` и т.д.), а не в `inCSV/`. После скачивания файлы нужно перенести в `inCSV/` вручную. В URL зашит устаревший query-параметр `?1721899999426`. Загрузка идёт с `--no-check-certificate`.

Источник файлов:

- `https://opendata.digital.gov.ru/downloads/ABC-3xx.csv`
- `https://opendata.digital.gov.ru/downloads/ABC-4xx.csv`
- `https://opendata.digital.gov.ru/downloads/ABC-8xx.csv`
- `https://opendata.digital.gov.ru/downloads/DEF-9xx.csv`

## Формат CSV

Кодировка UTF-8, разделитель `;`, первая строка — заголовок (её парсер пропускает). У заголовка есть BOM. Поля:

| Индекс | Колонка CSV | Смысл |
|---|---|---|
| 0 | АВС/ DEF | код ABC или DEF, обычно 3 цифры |
| 1 | От | начало 7-значного хвоста диапазона |
| 2 | До | конец хвоста, включительно |
| 3 | Емкость | размер диапазона |
| 4 | Оператор | наименование оператора |
| 5 | Регион | регион; несколько значений разделяются `\|` и хранятся как одна строка |
| 6 | Территория ГАР | территория по ГАР, тоже может содержать `\|` |
| 7 | ИНН | ИНН оператора |

Пример строки: `900;0000000;0061999;62000;ООО "...";Краснодарский край;Краснодарский край;7743895280`.

Разбор строки — регулярное выражение из восьми групп `.+`, разделённых `;`. Поле с символом `;` внутри строку ломает. Кавычки в названии оператора не являются синтаксисом CSV и остаются частью текста.

## База

Файл: `db.sqlite/numeration_registry.db`. Одна таблица `numbers`. Отдельных индексов нет: `fullnumber INTEGER PRIMARY KEY` совпадает с `rowid`, поиск по нему — точечный.

| Колонка | Тип | Откуда |
|---|---|---|
| `abc_def` | INTEGER | код ABC/DEF |
| `number` | INTEGER | 7-значный хвост конкретного номера |
| `fullnumber` | INTEGER PK | `7` + код + хвост из 7 цифр с ведущими нулями |
| `from_number` | INTEGER | начало исходного диапазона |
| `to_number` | INTEGER | конец исходного диапазона |
| `amount` | INTEGER | ёмкость диапазона |
| `operator` | TEXT | оператор |
| `region` | TEXT | регион |
| `territoriya_gar` | TEXT | территория ГАР |
| `inn` | TEXT | ИНН |

`parsetodb.py` для каждой CSV-строки строит список номеров `range(от, до + 1)` и вставляет его одним `executemany` внутри транзакции. Полный номер считается так: `7{abc_def}{хвост:07d}`. Повторный прогон упирается в `PRIMARY KEY`: конфликта `INSERT OR REPLACE` нет, пачка с уже существующим номером откатывается.

На текущих выгрузках файл базы около 126 ГБ (`page_size` 4096, порядка 3.3×10^7 страниц). Размер такой, потому что в таблице лежит каждый номер диапазона, а не сам диапазон. `COUNT(*)` по этой базе дорогой. Схему смотреть так:

```bash
sqlite3 "file:db.sqlite/numeration_registry.db?mode=ro" "PRAGMA table_info(numbers);"
```

## Бот

`main.py` при импорте модуля:

1. читает `.env`;
2. открывает `access.log` на дозапись;
3. открывает SQLite-соединение и курсор на всё время процесса;
4. создаёт `Bot` и `Dispatcher`.

Команды:

- `/start` — текст с просьбой прислать номер в виде `7<код><номер>`.
- любое другое сообщение — поиск.

Нормализация входа: из текста удаляются `-`, `(`, `)`, пробел и `+`. Ожидаемый вид после нормализации — 11 цифр, начиная с `7`. Проверки длины и того, что остались только цифры, нет.

Запрос: `SELECT * FROM numbers WHERE fullnumber=` и сразу конкатенация текста пользователя. Ответ при нахождении: `operator (region)`, то есть колонки 6 и 7 результата `SELECT *`. Иначе: `Номер не найден.`

В `access.log` и stdout пишутся исходный номер, оператор, регион, имя, username, id пользователя Telegram и время запроса. Формат лога: `исходный номер|оператор|регион|имя|@username|id|секунды`.

Запуск из корня:

```bash
source .venv/bin/activate
python main.py
```

`asyncio.run(main())` блокируется на `dp.start_polling`. Соединение с базой закрывается строкой `con.close()` на уровне модуля после выхода из polling.

## Ограничения, которые видны по коду

Их стоит учитывать при правках, чтобы не размножить текущее поведение.

- Текст пользователя подставляется в SQL конкатенацией. Нечисловой ввод даёт ошибку SQLite или меняет запрос. Параметры запроса (`?`) здесь обязательны.
- Соединение и курсор одни на процесс. Вызов `cursor.execute` синхронный и выполняется внутри async-обработчика, то есть блокирует event loop на время чтения с диска. Для точечного поиска по первичному ключу это обычно коротко, но соединение `sqlite3` нельзя свободно отдать другому потоку.
- Оба обработчика называются `cmd_start`. На маршрутизацию это не влияет: их различают декораторы.
- Материализация диапазона в список в `expand_numbers_pool` держит весь диапазон в памяти до вставки. Крупная ёмкость — это длинный список кортежей.
- `f.close()` после цикла ссылается на файл последней итерации. Если CSV в `inCSV/` нет, будет `NameError`. `with open` файл и так закрывает.
- `getcsv.sh` и `parsetodb.py` не связаны: скрипт загрузки не кладёт файлы туда, откуда их читает парсер.
- Повторная загрузка тех же диапазонов не идемпотентна из-за первичного ключа без `OR REPLACE` / `OR IGNORE`.
- Лог содержит номер телефона и идентификаторы Telegram. `access.log` в `.gitignore` не указан.
