# Импорт снимков и история версий

[← Оглавление](project-docs.md)

## Команды

```bash
./getcsv.sh                                                        # скачать снимок в inCSV/archive/YYYYMMDD/
./getcsv.sh 20261004                                               # то же с явной датой каталога

.venv/bin/python -m checkph.importer --backfill                    # все inCSV/archive/YYYYMMDD по порядку
.venv/bin/python -m checkph.importer --dir inCSV/archive/20261004  # один снимок, дата из имени каталога
.venv/bin/python -m checkph.importer --dir /path --date 2026-10-04 # дата явно
.venv/bin/python -m checkph.importer --backfill --db other.db --archive /path/to/archive
```

`--backfill` перебирает каталоги вида `YYYYMMDD` по возрастанию имени, дату берёт из имени, уже импортированные даты пропускает. Каталоги с другими именами игнорируются. По каждому снимку в лог выводится сводка: сколько версий открыто, закрыто, без изменений, сколько операторов новых и переименовано.

## Алгоритм diff-импорта (`importer.import_snapshot`)

Одна транзакция на снимок.

1. Если `import_batch` с такой `source_date` уже есть — выход без изменений (идемпотентность). Если дата не новее последней импортированной — ошибка: порядок импорта нарушен.
2. Снимок читается и валидируется `csv_reader.read_snapshot()` (см. [03-csv-format.md](03-csv-format.md)).
3. Создаётся `import_batch` с `sha256` файлов и числом диапазонов.
4. Операторы. Ключ — ИНН, при его отсутствии — имя. Для каждого ключа: самое частое написание в снимке становится `operator.name`; все написания попадают в `operator_name_variant` (`first_seen_batch` при первом появлении, `last_seen_batch` обновляется).
5. Диапазоны. Текущие открытые версии загружаются в словарь по ключу `(code, from_number, to_number)`, снимок сравнивается по значению `(operator_id, region_raw, gar_raw)`:

| Ситуация | Действие |
|---|---|
| есть в базе, нет в снимке | закрыть версию: `valid_to_batch = batch` |
| нет в базе | открыть версию: `valid_from_batch = batch` |
| есть, но значение отличается | закрыть старую, открыть новую |
| совпадает | ничего |

Смена написания имени оператора без смены ИНН версий диапазона не создаёт — она отражается только в `operator` и `operator_name_variant`. Это принципиально: в снимке 2024‑11‑11 реестр массово перевёл имена в верхний регистр (213 тыс. строк), и при хранении имени текстом это выглядело бы как 213 тыс. изменений.

## Снимки в архиве

| Каталог | Дата в `import_batch` | Диапазонов | Открыто | Закрыто | Без изменений |
|---|---|---|---|---|---|
| `20240724` | 2024‑07‑24 | 443 256 | 443 256 | 0 | 0 |
| `20240809` | 2024‑08‑09 | 439 753 | 17 706 | 21 209 | 422 047 |
| `20240913` | 2024‑09‑13 | 439 867 | 1 606 | 1 492 | 438 261 |
| `20241111` | 2024‑11‑11 | 440 914 | 6 031 | 4 984 | 434 883 |
| `20261004` | 2026‑10‑04 | 451 099 | 82 559 | 72 374 | 368 540 |

Оговорка про `20240724`: дата взята из имени каталога по решению владельца проекта. По содержимому этот снимок новее `20241111` — содержит написания операторов, появившиеся в реестре между сентябрём и ноябрём 2024, и больше диапазонов. Поэтому у части диапазонов история содержит переходы `2024‑07‑24 → 2024‑08‑09`, которые в реестре шли в обратную сторону. Если дата будет уточнена, порядок пересобирается заново: удалить `registry.db`, переименовать каталог, выполнить `--backfill`.

## Пересборка

База целиком выводится из каталогов архива. Для пересборки достаточно удалить файл базы и выполнить `--backfill`; данные слоя 3 (наблюдения) при этом теряются — их нужно переносить отдельно, если они есть.
