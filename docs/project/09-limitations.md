# Известные ограничения

[← Оглавление](project-docs.md)

## Данные

- `region_raw` и `gar_raw` хранятся строкой как в выгрузке. Запрос «все диапазоны региона» потребует разбиения на справочник `region` и связь M:N; при этом в ABC‑8xx встречаются значения вида «Российская Федерация, кроме …», которые на список не раскладываются, поэтому исходную строку в любом случае стоит сохранять.
- Снимок `archive/20240724` по содержимому новее `20241111`, но импортирован первым по решению владельца проекта — см. [05-import.md](05-import.md).
- История реестра есть только с 2024‑07‑24; более ранних снимков в архиве нет.

## Обогащение

- Интеграций с внешними источниками (банки, спам-базы) нет — есть только API записи наблюдений в `checkph/enrichment.py`.
- `owner_name` — персональные данные. Перед подключением источников нужно основание обработки по 152‑ФЗ и срок хранения наблюдений.
- `lookup_event` и `access.log` содержат номера телефонов и идентификаторы Telegram.

## Инфраструктура

- Один процесс бота, одно соединение SQLite с блокировкой; этого достаточно для текущей нагрузки, горизонтального масштабирования нет.
- Линтера, Docker и CI в репозитории нет.
- Старый файл `db.sqlite/numeration_registry.db` (134 ГБ, таблица `numbers` с каждым номером строкой) больше не используется и подлежит ручному удалению.

## Вне текущего этапа

- Материализованная проекция «номер → диапазон» для внешних потребителей (при необходимости — в PostgreSQL, а не SQLite).
- Справочники регионов и территорий ГАР.
- Команда бота для показа истории номера (`lookup.history` реализован, в бота не выведен).
