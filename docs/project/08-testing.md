# Тесты

[← Оглавление](project-docs.md)

```bash
.venv/bin/python -m pytest -q
```

Тесты в `tests/` работают на базе во временном каталоге (`tmp_path`) и на мини-снимках CSV, которые создаёт `tests/conftest.py::write_snapshot(root, name, rows)`. Реальные данные из `inCSV/` не используются, сеть не нужна.

| Файл | Что проверяет |
|---|---|
| `test_importer.py` | первичный импорт; повторный импорт той же даты — без изменений; одинаковый снимок не создаёт версий; переименование оператора без смены ИНН не создаёт версий, но обновляет `operator.name` и `operator_name_variant`; смена ИНН или региона закрывает и открывает версию; удалённый диапазон закрывается; разбиение диапазона на два; пересечение диапазонов отклоняется до записи в базу; снимок с датой не новее последней отклоняется; оператор без ИНН идентифицируется по имени; каноническим становится самое частое написание; `backfill` идёт по порядку имён каталогов и идемпотентен |
| `test_lookup.py` | `normalize`, `split_number`, `region_for_display`; попадание, промах, границы диапазона, диапазон из одного номера, другой код; `resolve` видит только открытую версию; `history` показывает версии и исчезновение диапазона; `resolve` подхватывает наблюдения слоя 3 |
| `test_enrichment.py` | ленивое создание `phone_number` и `data_source`; `v_number_owner_current` отдаёт последнее наблюдение; `v_number_spam_current` игнорирует старые наблюдения; номер вне диапазона отклоняется схемой |
| `test_bot.py` | `format_answer` без обогащения, с `-` в регионе, с владельцем и спамом; `Repository.resolve` и `log_lookup` |
| `test_sync.py` | одинаковый хеш каталога и zip; `backfill` читает zip; упаковка существующих каталогов; индекс без изменений ничего не качает; та же дата/хеш не создаёт batch; новый хеш пишет zip и импортирует; битый CSV уходит в `_rejected` |

Фикстуры: `con` — открытое соединение с применённой схемой; `snapshots` — каталог для мини-снимков. HTTP в `test_sync` — локальный сервер, сеть портала не нужна.
